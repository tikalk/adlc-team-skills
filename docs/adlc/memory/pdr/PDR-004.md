# PDR-004: Hybrid tiered supervision — human gates at promote, canary-expand, merge

## Context

**Problem/Opportunity:**
A rollout crosses blast-radius boundaries (staging→prod-canary, canary→full, merge execution) where agent judgment alone is insufficient — yet gating every 5%→25%→50% step would turn the factory's unattended promise into approval toil. The supervision model is the most sensitive UX call in this skill: too many gates and nobody uses it, too few and it ships damage autonomously.

**Market Forces:**
* All sibling orchestrators default to `hybrid` with hard human gates (Intent Gate, clarify gates, Merge Gate); `factory-tickets`/`factory-clean` prove the read-only end of the spectrum.
* `/ship` has no gate mechanism at all — its "no one monitoring the deploy" red flag is advisory, which the factory's gate vocabulary exists to fix.

## Decision

**Decision Statement:**
`factory-deploy` runs `hybrid` with one deploy-owned Deploy Gate authorizing the release at three checkpoints — (1) promote (staging→prod-canary), (2) canary→full expansion start, (3) merge execution — approvable by any human (code-owner or others) with identity recorded; everything else (health checks, log collection, threshold evaluation, changelog preview) runs autonomously. The Deploy Gate is distinct from the review-owned Merge Gate (merge-readiness, PDR-002): deploy executes the merge only when both are green.

**Rationale:**
* Mirrors the sibling supervision defaults, so teams learn one gate mental model across the factory.
* Three checkpoints cover the three irreversible-or-blast-radius actions; expansion percentages auto-advance on green thresholds per PDR-009, so toil stays flat.

**Rationale:**
* Mirrors the sibling supervision defaults, so teams learn one gate mental model across the factory.
* Three gates cover the three irreversible-or-blast-radius actions; expansion percentages auto-advance on green thresholds per PDR-009, so toil stays flat.
* Any-human (not code-owner-only) approval keeps night/weekend releases unblocked while preserving a named accountable approver on the audit trail.

## Consequences

**Positive:**
* Blast radius is always human-approved; routine work never waits on a human.
* Gate decisions land on the comment bus as `decision` outputs — resumable and auditable across sessions.

**Negative:**
* Three gates still slow trivial releases (mitigated by short-path route classification for low-risk releases).
* Any-human approval is weaker than code-owner-only; a careless approval can wave through a bad canary.

**Neutral / Acceptance:**
* Gates are halting, not advisory: without approval the run pauses (lease-kept, resumable), never proceeds.

## Alternatives Considered

* **Autonomous with auto-rollback (human only on red)**: fastest. Rejected — contradicts the factory's non-negotiable gates (Intent, clarify, Merge); wrong default for a v1.
* **Interactive step-by-step (gate every percentage)**: maximum control. Rejected — toil-heavy, defeats unattended purpose; thresholds already decide expansion steps mechanically.
* **Code-owner-only approvers**: strongest accountability. Rejected — blocks releases when the owner is away; approver identity is recorded either way.
