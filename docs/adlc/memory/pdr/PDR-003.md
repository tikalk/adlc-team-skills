# PDR-003: Changelog as tracker-generated release artifact with SemVer per spec-kit

## Context

**Problem/Opportunity:**
Releases ship without notes or with notes reconstructed from memory at release time — half the impact is missing and consumers can't answer "what changed, do I care?" The repo already follows Keep a Changelog + SemVer, and `agentic-sdlc-spec-kit/RELEASE.md` pins the mechanics (decision tree, tag-as-truth, commit prefixes), but no factory skill owns the release-notes step.

**Market Forces:**
* `git-workflow-and-versioning`: changelog is curated human prose grouped by impact, written with the change — never a dumped commit log; version derived from the tag.
* spec-kit `RELEASE.md`: PATCH for fixes, MINOR for features, MAJOR for breaking (mixed→MINOR); tag format `agentic-sdlc-vX.Y.Z`; strict `X.Y.Z` validation.

## Decision

**Decision Statement:**
`factory-deploy` cuts the release as: (1) SemVer bump from the spec-kit decision tree, (2) tag as source of truth (no tag = no release; version derived from tag; strict `X.Y.Z` gate in `verify`), (3) changelog section generated from linked tracker issues/PRs grouped by impact (Added/Fixed/Deprecated/Removed/Security), approved via dry-run preview at the gate.

**Rationale:**
* Split duty resolves the authorship tension: authors write entries with their change (impact fresh), deploy assembles `Unreleased`→versioned section and cuts the tag — nothing is reconstructed from archaeology.
* Tracker-generated (not hand-curated, not raw git log): titles carry issue-type metadata the grouping needs; the preview+approval gate is where curation happens — the approver edits the generated draft before it lands.
* SemVer mechanics are borrowed verbatim from spec-kit instead of reinvented, including commit-prefix convention.

## Consequences

**Positive:**
* Every release is tagged, versioned by rule, and noted by impact — reproducible and consumer-readable.
* The strict-version gate fails the run early instead of shipping an unversioned artifact.

**Negative:**
* Tracker-generated notes depend on issue hygiene (typed, linked issues); garbage titles produce garbage notes — mitigated by the approval-edit step.
* Tag naming must be parameterized per repo (spec-kit's `agentic-sdlc-v` prefix is not universal).

**Neutral / Acceptance:**
* Dry-run preview before every changelog/tag write (precedent: `factory-queue` dry-run gating).

## Alternatives Considered

* **Hand-curated entries only**: highest quality prose. Rejected — doesn't scale to agent-driven releases; curation now happens at approval time instead.
* **Raw git log as changelog**: zero effort. Rejected — explicit red flag in `git-workflow` ("commits are for you; the changelog is for consumers").
* **No changelog duty (deploy never touches it)**: no ownership clash. Rejected — releases would keep shipping without notes; the step stays orphaned.
