# Coexistence with Agentic SDLC Spec Kit

This document describes how to use `adlc-team-skills` alongside
`agentic-sdlc-spec-kit` in a single project without skill/command conflicts
or lifecycle redundancy.

## Recommended flow

```bash
# 1. Install adlc team skills, slash commands & event hooks
npx adlc-skills-cli add tikalk/adlc-team-skills -a opencode

# 2. Run the team-setup skill in your agent session
#    (links/clones your team-ai-directives repository)
/team-setup

# 3. Initialize Spec Kit — DO NOT pass --team-ai-directives
specify init --here --integration opencode
```

Do not pass `--team-ai-directives` to `specify init`. When that flag is
present, spec-kit installs its own `team-ai-directives` extension, which
generates `team-boot`, `team-discover`, and `team-skills` skills that collide
with the ones this repo installs. Omitting the flag keeps spec-kit's SDD
commands only and lets `adlc-team-skills` own the team-context layer.

## Why this works

- **Zero skill/command conflicts.** `adlc-team-skills` owns the Team, Product
  (PDR), Architecture (ADR), Evals, and LevelUp lifecycles. `spec-kit` owns
  Spec-Driven Development core commands (`/spec.specify`, `/spec.plan`,
  `/spec.tasks`, `/spec.implement`, `/spec.converge`, …). The two use
  different command naming conventions (hyphen vs dot) and different skill
  directories, so no file overwrites occur.
- **Automatic session bootstrap.** `adlc-team-skills` installs a native
  `session_start` event plugin that auto-injects `team-ai-directives`
  (constitution, CDR index, skills registry) into every agent session —
  keeping agents aligned with team directives from turn 1.
- **No command redundancy.** Spec Kit (`v0.16.0+adlc2` and later) no longer
  preinstalls the `levelup` extension by default, eliminating duplicate
  `/levelup.*` vs `/levelup-*` commands. The extension remains bundled and
  available on demand via `specify extension install levelup`.

## Ownership summary

| Domain / Layer | Owned By | Provided Artifacts |
|---|---|---|
| `team-ai-directives` context | `adlc-team-skills` | Auto `team-boot`, `/team-discover`, `/team-constitution`, `/mission-brief` |
| PDR, ADR, Evals & LevelUp | `adlc-team-skills` | `/product-*`, `/architect-*`, `/evals-*`, `/levelup-*` |
| Spec-Driven Feature Dev | `spec-kit` | `/spec.specify`, `/spec.plan`, `/spec.tasks`, `/spec.implement`, `/spec.converge` |
| Agent Context & Git | `spec-kit` | Auto `AGENTS.md` / `CLAUDE.md` plan updates & git branch/commit integration |

## On-disk layout after install

```
project-root/
├── .adlc/
│   └── init-options.json              ← team-ai-directives repo path (adlc)
├── .agents/
│   ├── dispatcher.mjs                 ← event dispatcher (adlc)
│   └── skills/                        ← 30 SKILL.md files (adlc)
├── .opencode/
│   ├── commands/                      ← hyphen-named (adlc) + dot-named (spec-kit)
│   ├── plugin/
│   │   ├── adlc-skills-events.ts      ← session_start hook (adlc)
│   │   └── speckit-events.ts          ← agent-context refresh (spec-kit)
│   └── skills/                        ← spec-kit skills (none from preinstalled extensions)
├── .specify/                          ← spec-kit config, extensions, presets, scripts
├── .events.json                       ← adlc event manifest
├── opencode.json                      ← spec-kit plugin registration (auto-discovery still works)
├── AGENTS.md                          ← managed by both via separate marker sections:
│   <!-- TEAM_AI_DIRECTIVES START -->  ← adlc team context
│   <!-- SPECKIT START -->             ← spec-kit plan reference
└── PRD.md / AD.md / evals/            ← generated by adlc skills on demand
```

## Session start behavior

Both toolkits hook `session_start` independently and do complementary work:

1. **adlc plugin** — runs `team-boot` script, reads `.adlc/init-options.json`,
   assembles the team constitution + CDR index + PDR/ADR indexes, and injects
   the result into the first user message.
2. **spec-kit plugin** — runs the `agent-context` extension's `session_start`
   event, which refreshes the `<!-- SPECKIT START -->…<!-- SPECKIT END -->`
   section in `AGENTS.md` with the current plan reference.

The two plugins are auto-discovered by opencode from `.opencode/plugin/` —
no manual registration in `opencode.json` is required.

## AGENTS.md coexistence

Each toolkit manages only its own marker-bounded section in `AGENTS.md`:

- `<!-- TEAM_AI_DIRECTIVES START -->…<!-- TEAM_AI_DIRECTIVES END -->` —
  adlc team-context compliance directive (managed by `team-setup`).
- `<!-- SPECKIT START -->…<!-- SPECKIT END -->` — spec-kit plan reference
  and team-boot invocation directive (managed by the `agent-context`
  extension).

Neither toolkit touches the other's section. If you hand-edit content outside
both marker pairs, it is preserved by both.

## Optional: enable non-overlapping spec-kit extensions

After running `specify init`, you can optionally enable spec-kit extensions
that have no `adlc-team-skills` equivalent:

```bash
specify extension install git     # git branching & commit workflow
specify extension install tdd     # RED→GREEN→REFACTOR TDD cycle
specify extension install edd     # evaluation-driven verification layer
```

Avoid enabling `team-ai-directives`, `architect`, `product`, or `evals`
extensions — those overlap with `adlc-team-skills` skills and would reintroduce
command/skill duplication.

## Troubleshooting

**`/team-discover` and `/team.discover` both appear.**
You likely ran `specify init --team-ai-directives` (step 3). Remove the
generated spec-kit skills to restore adlc as the sole owner:

```bash
rm -rf .opencode/skills/team-boot .opencode/skills/team-discover .opencode/skills/team-skills
```

**`team-boot` does not fire at session start.**
Verify `.events.json` exists at the project root and that
`.opencode/plugin/adlc-skills-events.ts` is present. Re-run
`npx adlc-skills-cli add tikalk/adlc-team-skills -a opencode` if either is
missing.

**Duplicate `/levelup.*` and `/levelup-*` commands.**
Ensure you are running spec-kit `v0.16.0+adlc2` or later. If an older version
installed the `levelup` extension, disable it:

```bash
specify extension disable levelup
```
